# OpenMAVIS 适配 Layout0921 四目配组数据及完整回放验证

## 目标与约束

在 `codex/openmavis-layout0921-prepared` 分支复用 Basalt 准备阶段的 1195 组四目图像，完成无 GUI 的 IMU_MULTI 回放。验证四路输入、IMU 初始化、连续跟踪和轨迹导出；不进行 mocap/Basalt 精度比较，不声称完成 GUI 验证。不修改原始数据、Basalt 历史结果或标定 JSON，不自动合并和推送。

## 实施步骤

1. 创建分支并保留用户 YAML，写入本计划及独立中文验证记录。
2. 主工程使用 C++14，修复本机 Pangolin 编译兼容性；专用脚本默认 4 任务构建 DBoW2、g2o、新入口与原入口，已有词典不重新解压。
3. 修正 YAML 四个矩阵闭合括号缩进、Camera.fps=30、Camera.RGB=0；保留内外参、噪声和优化参数。OpenCV 实际解析，并核对 `T_b_c` 和 `inverse(T_b_c1)*T_b_c2`。
4. 新增 multi_inertial_prepared，原示例接口不变。cam0–3 对应 Camera1–4，分别读取 CSV 文件名，要求等长、严格递增、逐行同时间；不再次配组、不静默截断。检查全部文件和逐帧解码尺寸。
5. 整数纳秒时间用于索引，传入 SLAM 的时间为 `(t_csv_ns+2631359)*1e-9`，只应用一次。IMU 原时钟/轴顺序不变，检查单调、有限值、首尾覆盖；保留首帧前一个样本，每帧提交到首个不早于该帧的样本，每条仅提交一次，让现有预积分队列保留边界。
6. 新运行目录保存命令、Git 版本及差异、实现/配置/输入哈希、准备阶段来源、日志、逐帧状态、四路特征、初始化和地图事件、轨迹与汇总。原导出器只导出最大地图，明确时间单位和坐标定义。
7. 首次保持当前模型、重叠区、特征数与优化阈值。失败时检查读取、时间、特征、反投影，不降低验收门限。若需 mask，保留首次结果并单独报告依据和对照。

## 新入口接口

必填：`--vocabulary`、`--settings`、`--dataset`、`--output`、`--cam-time-offset-ns`。输出目录必须新建。可选：`--max-frames`、`--viewer`、`--realtime`，默认全量、无 GUI、不限实时速率。增加 `--validate-only` 用于不启动 SLAM 的输入解码检查。

运行脚本默认本数据和 2631359 ns，可显式覆盖。状态读取接口只供 TrackMulti 返回后的同一调用线程使用，不改变优化逻辑。

## 验证与验收

- 数据审计：1195 组、4780 张图像、20219 条 IMU、配置可解析，校正时间在 IMU 覆盖内。
- 针对性测试：四路时间不一致、缺图、坏图、重复时间、IMU 覆盖不足、空输入，以及偏移只应用一次、IMU 边界不越界。
- 构建新旧四目入口；前 300 组短回放，之后全量 1195 组真实回放。
- 完整回放正常退出，轨迹有限且时间递增，存在实际 IMU 初始化证据。
- 初始化后 OK 比例至少 95%，最终有效跟踪，初始化后无重置；报告最长非 OK 时段、地图数量、处理/跟踪/导出行数。未满足时标记入口已适配、跟踪验收未通过，保留原因。
- 执行相关测试及 git diff --check；中文记录给出可复制命令、真实指标、结果目录、剩余限制。构建和运行产物不纳入版本控制。

以上是回放和连续性验收，不是绝对精度验证。
